## 프롬프트 (아래를 그대로 PPT 도구에 붙여넣을 것)

아래 내용으로 5장짜리 발표 슬라이드를 만들어줘. 대상은 DB 수업을 막 들은 동료
수강생들이고, 발표 시간은 3~5분. 톤은 담백하고 실무적으로. 각 슬라이드는
제목 + 핵심 불릿 2~4개로 간단하게 구성해줘.

### 슬라이드 1 — 표지
- 회의록 STT 요약 서비스
- STT 텍스트 → LLM 구조화 추출 → Firestore 저장·조회
- LG CNS AI Campus DB 파트 미니 프로젝트 (2인)

### 슬라이드 2 — 뭘 만들었나
- 지난주(LLM 구조화 출력) + 이번 주(Firestore) 학습 내용을 하나로 통합
- 앱(정적 HTML) → FastAPI 백엔드 → LLM 체인 → Firestore, 앱은 Firestore에
  직접 접근 안 함(서비스 계정 키 유출 방지)
- (다이어그램 자리: PRD-MVP.md 4절)

### 슬라이드 3 — 왜 Firestore(NoSQL)인가
- RDBMS였다면: `meetings`+`decisions`+`action_items` 3테이블, 매번 JOIN
- Firestore: `decisions`·`action_items`가 문서 안에 배열로 중첩 — 문서 하나만
  읽으면 끝, 항목 개수가 들쭉날쭉해도 스키마 변경 불필요
- "회의 단위로 통째로 읽는 조회 패턴"일 때 Firestore가 유리
- (비교 자리: ERD.md 3절, 실제 저장된 문서 캡처는 ERD.md 2절)

### 슬라이드 4 — 최소 보안 조치 + 실제 검증
- 서비스 계정 키는 서버에만 / 입력 길이 제한 / Firestore는 백엔드 경유만 허용
- 프롬프트 인젝션 방어: 회의 텍스트 안에 지시문을 섞어도 무시하도록 구현
- 실제 공격 텍스트로 테스트 → 방어 확인(3회 재현) — "계획만이 아니라 검증까지"
- (표 자리: PRD-MVP.md 6절 방어 전/후 비교)

### 슬라이드 5 — 데모 & 마무리
- (라이브 데모 또는 스크린샷) 텍스트 붙여넣기 → 추출 결과 → 목록/상세 확인
- 이번엔 안 한 것: 수정/삭제 기능, 인증, PII 마스킹 — Main 단계로 이월
